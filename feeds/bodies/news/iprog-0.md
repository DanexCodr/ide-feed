A Rust framework for building full-stack apps that prioritizes simplicity and productivity has been released by the Tokio team. Topcoat is described as a modular, batteries-included framework that uses server-side rendering, with reactivity added through cross-compiled Rust expressions rather than WebAssembly. Topcoat includes views, components, mailers, and an ORM (Toasty). The developers say Topcoat aims to make building web apps with Rust as productive as any other language. Topcoat renders all markup on the server. Components can be async and query the database directly, eliminating all the traditional boilerplate needed for a separate API layer.  Topcoat starts with signals and a special runtime expression syntax inside the view! macro that consists of a fully type-checked subset of Rust that can be transpiled to JavaScript and re-run in the browser. The idea is to have as much of the rendering and business logic on the server, and only sprinkle in runtime expressions to bridge the latency gap, for example by revealing a loading spinner or changing some class attributes. The developers say that with a system like this, it is possible to build basic interactivity while avoiding server roundtrips entirely. so avoiding the need for a wasm bundle and the client build step. However, by themselves, Topcoat's runtime expressions fall short when you need to make changes to the structure of the markup itself. To fix this, the developers added shards, which are a special type of component that can be re-rendered on the server whenever their arguments change. Developers can mark a component as a shard when an update does need the server, like fresh search results. Topcoat will re-render it on the server whenever one of its $(...) arguments changes and swap the new HTML in place. If you need to update the UI in response to a server-side state change, the way this is handled in Topcoat is via either a live! or an emit! macro. A live! view is a special type of view! that can emit unlimited UI updates. Other ideas in Topcoat include the use of a view! macro for mixing HTML with Rust control flow, and an asset pipeline with content-hashed URLs. There's also a Tailwind integration that works without Node.js, and integration with the Toasty ORM.  One of the headline design choices in Topcoat is the $(...) expression. These are ordinary type-checked Rust fragments that Topcoat evaluates on the server for the initial render and also translates to JavaScript, so they re-run instantly in the browser without a WASM bundle or separate client build step. The version just released also adds support for server-push. Instead of streaming only for the initial page load, Topcoat can open a WebSocket connection from the browser to the server and subscribe to UI changes over long-lived connections.  Topcoat 0.9 is available now on GitHub.
