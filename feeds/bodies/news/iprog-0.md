GemDB has launched GemDB Code, a free Visual Studio Code extension that delivers a database where the code is the schema. The extension ships with a Jupyter Notebook kernel and an MCP server for natural-language queries.  GemDB (formerly GemTalk Systems) are the developers of GemStone/S, a highly scalable, high-performance object-oriented transactional database. GemStone/S is a native Smalltalk application that doesn't use tables. It stores and processes complex business objects directly in memory, eliminating object-relational mapping (ORM) overhead.  The extension aims to overcome a developing need, where AI agents handle the creation of databases, causing a gap between the ease of creating a database, and the difficulties of managing and working with that database. GemDB says that while recent analyst reports have found that AI can accelerate coding by 30–40%, overall team productivity often rises less than 10% when downstream steps remain manual, because "the bottlenecks simply move." Those bottlenecks increasingly center on the database. At the moment, developers need to deal with the infrastructure of coordination tools, synchronization layers, and ORM abstractions that manage the gap between application code and database schemas. The GemDB team says these approaches reduce friction, but they preserve the underlying problem: code and data remain two separate systems that must stay in sync. To date, the industry has responded by building coordination tools, synchronization layers, and ORM abstractions that manage the gap between application code and database schemas. The GemDB team says these approaches reduce friction, but they preserve the underlying problem: code and data remain two separate systems that must stay in sync.  GemDB aims to overcome this because objects persist exactly as they exist in application code, and changing the code changes the schema. There's no need for mapping, migration, or synchronization because there is nothing to synchronize. This has been achieved because of the use of Smalltalk as the underlying language.  The way the new VS Code extension works is that when a developer or AI coding agent creates or modifies an object and commits it, the object persists as-is with full ACID transactional guarantees. GemDB Code packages the GemDB object database engine as a self-contained VS Code extension. The database downloads and configures automatically on first activation.  A developer or coding agent creates an object, commits it, and the object persists with full transactional guarantees. When that object needs to change, the developer or agent updates the code and commits again. Adding new many-to-many relationships, a change that would typically require new join tables, data tables, foreign key definitions, and backfill migration scripts in a relational database, requires only adding a field to an object. _"We've spent decades accepting a separation between code and data that was not inevitable,"_ said Sandeep Parikh, Chief Product Officer, GemDB. _"Any builder working with a coding agent eventually hits the same wall, where the agent writes application logic in minutes, but the database layer still expects manual coordination, migration scripts, and scheduled downtime. GemDB removes that wall entirely. When your objects are the database's objects, schema changes become code changes, and code changes are what AI agents do best.”_ The extension ships with a built-in Jupyter Notebook kernel for interactive development against a live database and an MCP server that enables natural-language queries through any chat-based AI agent, so developers can ask questions of their data conversationally without writing formal queries. The extension supports Python at launch, with support for additional languages planned. Licensed standalone editions, GemDB Advanced and GemDB Enterprise, will be available for production workloads in 2027.
