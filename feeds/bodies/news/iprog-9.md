PyTorch 2.15 has been released, with improvements including the promotion of its rewritten NCCL backend to default status, a new flight recorder for hang diagnostics, and improved hardware support. PyTorch is an open-source deep learning library, originally developed by Meta and now being developed with support from the Linux Foundation. It is a Python package that provides tensor computation (like NumPy) with strong GPU acceleration; and deep neural networks built on a tape-based autograd system. It is designed to be flexible and modular for research, with the stability and support needed for production deployment. PyTorch supports dynamic computation graphs, so researchers and developers can iterate quickly, and the developers say its Pythonic design and deep integration with native Python tools make it accessible for building and training deep learning models at scale. The headline change of the new release is that the rewritten NCCL backend becomes the default, with a flight recorder that dumps on hangs. NCCL is the NVIDIA Collective Communications Library, a software library that implements high-performance multi-GPU and multi-node communication primitives for deep learning and parallel computing. It is used in PyTorch so GPUs can communicate with each other in single-node or multi-node clusters. This is a key requirement for feeding new data to large neural networks and for building and maintaining LLMs. The problem was that the existing NCCL interface was prone to deadlocks and the performance was unpredictable, because of the number of communicators it created per process group. In contrast, the rewritten backend enforces the rule that each process group can have only one communicator during initialization. This does away with the problems caused by multiple active communicators.  VIDEO In the new backend, communicators are created eagerly with the process group, and reconfiguration can opt into a shrink/grow fast path (NCCL 2.29 or newer) so surviving ranks skip a full bootstrap. To make the backend debuggable in production, a backend-agnostic flight recorder writes a post-mortem to disk when a collective hangs, and watchdog health is published to the debug server so a timeout on any rank triggers flight-recorder dumps from every rank. At cluster scale, a single stalled GPU can halt an entire training run, and finding the cause has often meant reproducing the failure by hand. The flight recorder captures what each rank was doing at the moment of the hang. The new version also adds one-sided transports with a NIXL Backend. Transports connect to a peer through a store, without needing a process group or collectives, and Transport read and write streams queue transfers on a CUDA stream so they can be captured with torch.cuda.graph.  Elsewhere, FSDP2 and pipelining gain finer memory and communication control, with fp32 for precision-sensitive parameters, CUDA-graph-captured gradient accumulation, and gradient reduction overlapped with compute. PyTorch 2.15 is available now.  .
