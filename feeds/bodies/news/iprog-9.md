NestJS 12 has been released, with improvements to the framework, the CLI, the default tooling, and the documentation. NestJS is an open source TypeScript Node.js framework for creating efficient and scalable server-side Node.js applications. Its modular architecture was inspired by Angular. NestJS catches TypeScript errors at compile time while remaining compatible with plain JavaScript. It organizes code into distinct, reusable modules that group related controllers and providers. It has a built-in DI container powered by decorators to manage component dependencies, and supports REST APIs, GraphQL, WebSockets, microservices, and database ORMs, It runs on Express by default but can be switched to Fastify for higher performance.  The headline change in v12 is that the NestJS core packages now ship as ESM. Kamil Mysliwiec, the main creator and developer of NestJS, says this has been one of the most requested changes in the history of the project, and it finally aligns Nest with the direction the entire Node.js and TypeScript ecosystem has been moving toward for years. However, the transition is optional for application code. Modern Node.js supports require(esm), which means existing CommonJS projects can upgrade to the v12 packages and keep working without a rewrite. The NestJS CLI comes with an upgrade flow, and running it will update your Nest dependencies while preserving your existing module format. The upgrade doesn't convert source files to ESM; CommonJS projects stays as CommonJS projects, and everything keeps working thanks to require(esm).  The second improvement of note is that NestJS 12 introduces direct support for Standard Schema. Route parameter decorators such as @Body(), @Query(), and @Param() now accept a schema option, which takes any Standard Schema compatible object. This opens the door to validation flows built on libraries like Zod, Valibot, and ArkType.  Structured logging has also been added, so the ConsoleLogger now treats plain objects passed as additional arguments as structured parameters. In JSON mode, these parameters are nested under a params key by default, or spread onto the root object when you enable the flattenParams option. Mysliwiec says this makes the built-in logger play more nicely with log aggregation platforms without any third-party wrappers. This release also adds support for machine-readable error codes, and for route conflict diagnostics meaning the core router can now detect shadowed and duplicate routes for you.  NestJS 12 also ships alongside the new official @nestjs/observe SDK, which integrates natively with the framework through the new instrument application option. It hooks into Nest's own request lifecycle rather than bolting a generic Node.js agent onto the process. Once enabled, it automatically instruments incoming requests, background jobs, errors, logs, and traces, with no exporter to configure and no schema to design. NestJS 12 is available now.
