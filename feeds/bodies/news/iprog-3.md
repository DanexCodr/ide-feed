The Deno team is joining Cloudflare "to radically simplify self-hosting Workers and Durable Objects, so developers can use the same primitives in more places". A side effect of the move is that new work will cease on Deno. However, there will be another year of bug fixes and security updates, and the project will remain open source if anyone wants to keep working on it.  Deno is a server-side JavaScript runtime that was designed and led by Ryan Dahl, who created Node.js. Deno supports TypeScript and WebAssembly, and is built on the V8 engine and Rust. Dahl created Deno as an alternative to Node.js.  When Dahl created Node.js it was because he wanted a less memory hungry alternative to the Apache web server use in web application architecture. Node.js combined an event-driven, non-blocking architecture with the power of JavaScript, meaning developers could use JavaScript both on the client and the server. Built on Chrome’s V8 engine, NodeJS made it possible to develop scalable network solutions through an event-driven, non-blocking I/O model.  Node.js runs on around 30 million websites across the world, over 6.5% of all known websites, and powers nearly 9% of the world's top 1 million highest-trafficked sites.  Dahl says he created Deno to find more powerful abstractions similar to the way Node.js shows what a purely asynchronous programming model could enable. He said Deno was the result of him looking for places to simplify and remove capabilities while giving engineers ever more power. _"With Deno, we improved the experience of writing JavaScript, but we didn’t fundamentally change what developers had to assemble around the runtime. The bigger problems are around networked applications: distributing computation, coordinating state, data storage in general, and autoscaling to meet demand."_ The problem was that Deno developers still wanted Node.js compatibility, so limiting Deno's options for change. Last year Dahl launched celld, an open-source, self-hosted, distributed platform for running Cloudflare Durable Objects and related serverless APIs on your own machines. On the celld website, Dahl said that their replication of the Durable Objects architecture was a love letter to the architecture. Durable Objects is a single-threaded object with its own SQLite storage. Dahl said it provides "one of the best primitives distributed systems has been handed in years."  Dahl says that Cloudflare's Durable Objects provide _"a very powerful abstraction: the distributed singleton with a SQLite database. Each Durable Object is like a small, individually addressable server with its own relational database. Its JavaScript execution is single-threaded (which is easy to reason about), it handles WebSockets, and its local SQLite database can be accessed synchronously. By building a chat application using one DO per channel, you have sharded your data and WebSocket connections, and thus made your application scalable."_ On top of the Durable Objects abstraction, other services can be built: Queues, KV, Durable Execution (CF's Workflow API), even Git storage. Dahl describes Durable Object abstraction as simple yet incredibly powerful. However, Dahl says running this model outside of Cloudflare has remained difficult. There is Workerd, an open-source JavaScript and WebAssembly server runtime, that shares the core engine that powers Cloudflare Workers, making it portable for use outside of Cloudflare's managed cloud network, but its Durable Objects support is limited to a single instance. What Dahl wanted was a distributed version: IRC channels spread across machines, with the platform handling placement, routing, and durable storage. That was the thinking behind the creation of celld. It's written in Rust, with object storage as its only external service dependency. To run it, you manage many instances of celld and a single object storage bucket. Your application can contain many services without each requiring a separate infrastructure project. Dahl says the Deno team is joining Cloudflare to make the Workers programming model a mainstream way to build servers. _"By bringing celld and workerd together, we want it to be radically easy to build and operate distributed applications on your own infrastructure."_ All this sounds very interesting for moving to Cloudflare, but if you've a Deno app, what are your options? If you're running Deno Deploy, Cloudflare is offering migration support to Cloudflare Workers. Other developers will have to work out which way to jump - Node.js or Bun (recently bought and rewritten by Anthropic) seem the only choices.
