Reasoning as pathfinding in token space.

There’s an intuitive but simplified picture of reasoning: let a model think for longer, and it’ll be more likely to be correct. This aligns well with our human intuition: spend more time and effort on thinking and it’s more likely that we’ll arrive at a correct answer.

But this picture doesn’t seem to explain everything. During RL training, models learn to write longer chains of thought, and they get more accurate as they do. Yet if you take a trained model and force any one chain to run longer, it helps for a while, then stops helping.<sup>[1](https://alexwang.ai/posts/reasoning-as-pathfinding/#fn:1)</sup> Sometimes the answer even gets *worse*, as if it’s overthinking.<sup>[2](https://alexwang.ai/posts/reasoning-as-pathfinding/#fn:2)</sup> If a chain of thought were truly converging toward some optimum, more steps shouldn’t make it worse. So is it really the length of each chain that helps at inference time? Or is it something more subtle?

This post is my attempt to clarify this confusion (mostly for myself) by looking at reasoning as pathfinding through token space. We’ll see that RL maximizes the probability of finding a path from $x$ to $\Scal_x$, but individual paths are not guaranteed to converge to the correct answer. As a bonus, this perspective clarifies some odd observations about reasoning models, like unfaithful chains of thought and reward hacking.

## Reasoning as pathfinding[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#reasoning-as-pathfinding)

Ask a reasoning model the same math problem ten times and you’ll get ten different chains of thought. Rather than thinking of reasoning as one mysterious process heading toward an answer, let’s think of it as pathfinding in token space. There are many paths from the problem to a correct answer, and the model traverses one of them with each sample.

Consider the problem: “what’s $1 + 2 + 3 + \cdots + 10$”? One solution is to add the numbers one at a time: 1, 3, 6, 10, and so on up to 55. Another way is to pair them from the outside in: $1 + 10$, $2 + 9$, $3 + 8$, $4 + 7$ and $5 + 6$ each make 11, and five pairs of 11 make 55. Both of these paths land on the correct answer, 55.

We can think about reasoning as following this general pattern. We are given a starting point, the prompt, which we’ll call $x$.
We want to find a path $z$ that starts from $x$ and ends at a correct answer $y$. To tell whether a path lands in the right place, we assume we have a verifier $r(x, y)$ that returns 1 if $y$ is correct and 0 if it isn’t.

Since many paths land in $\Scal_x$, the success probability adds up over all of them. Let $\pi(z \mid x)$ be the probability that the model generates the path $z$ given the prompt $x$, and $y(z)$ for the final answer at the end of $z$. The probability of success is the probability of generating each path, times the probability that path lands in $\Scal_x$, summed over every path:

The second factor is just 1 if the path lands in $\Scal_x$ and 0 if it doesn’t, so we sum only the probability of paths that land in $\Scal_x$:

We’ll call $p_x$ the **success probability**. Maximizing this probability means our model will be more likely to sample a path that lands in $\Scal_x$.

Note that there are two ways of increasing this probability. Either the model can sample multiple paths to the same answer, each with a small probability, or the model can sample a single path to the answer with a very high probability. The success probability doesn’t care which one we get, but in practice we might want to prioritize specific paths or ensure diversity in the samples<sup>[3](https://alexwang.ai/posts/reasoning-as-pathfinding/#fn:3)</sup>.

## How do we boost our success probability?[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#how-do-we-boost-our-success-probability)

### Best-of-$k$ sampling[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#best-of--sampling)

The simplest way to pathfind is to have the model $\pi$ keep sampling paths $z$ until one lands in $\Scal_x$.

Since we assumed we had a verifier, we can do best-of-$k$ sampling, which samples $k$ paths and looks for a success. Each path misses with probability $1 - p_x$, so all $k$ miss with probability $(1-p_x)^k$, and the success probability rises from $p_x$ to

This is a guaranteed axis of compute-scaling. As long as $p_x > 0$, the success probability increases monotonically as we sample more paths, so spending more compute on more samples always helps, as seen early on by [Brown et al. 2024](https://arxiv.org/abs/2407.21787).
However, the scaling here is over the number of samples rather than the length of the paths (thinking longer).

### Train the model to generate better samples[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#train-the-model-to-generate-better-samples)

So far the model was fixed, so $p_x$ was fixed too. Can we change the model to increase $p_x$ itself?

Here’s a simple way to do this. Collect many prompts whose answers we can check. For each one, sample some paths from the model. We keep the paths that land in $\Scal_x$, and train the model on the ones we kept. Then repeat. Each round, we train the model to put more weight on the successful paths that it sampled. This loop is called rejection-sampling fine-tuning, and [STaR](https://arxiv.org/abs/2203.14465) was an early version of it for reasoning.

This also explains the first observation from the intro, that chains of thought get longer during RL training. Each step pulls the model toward the paths that landed, so if the paths that succeeded tended to be longer than the ones that failed (e.g. because they include backtracking behavior, gather more feedback from the environment, or just dumb luck), the model will learn to write longer paths.

## Amortization and generalization[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#amortization-and-generalization)

During RL training, we spend a lot of compute to search for good paths and then we train the model to generate those paths directly. Once trained, the model can produce the answer without spending all this extra compute on sampling multiple paths. This is called *amortizing* the search: we pay for it once during training, so we don’t have to pay for it every time we ask the model a question.<sup>[4](https://alexwang.ai/posts/reasoning-as-pathfinding/#fn:4)</sup> Since we train a *single model* on many prompts, the model can potentially *generalize* to new prompts it has never seen.

The hollow prompt is new and not seen before by the model, but the model generalizes to this new prompt after training. ## Revisiting some observations about reasoning[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#revisiting-some-observations-about-reasoning)

Once we see a reasoning model as a distribution trained to land in $\Scal_x$ given any $x$, a few odd facts about these models become clear.

### Chains of thought are not guaranteed to be faithful[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#chains-of-thought-are-not-guaranteed-to-be-faithful)

Our verifier above only checks whether the answer is correct. The reward is 1 if $y(z) \in \Scal_x$ and 0 otherwise, so the intermediate tokens $z$ are just a way for the model to get to the answer. Nothing requires those tokens to be true, or to explain the answer that follows, though of course these are often correlated due to the model’s pretraining.

If we want meaningful chains of thought, we need to adjust the rewards or the training objective.

### Reward hacking comes from both the verifier and the sampler[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#reward-hacking-comes-from-both-the-verifier-and-the-sampler)

We also assumed the verifier is never wrong, that $r(x, y)=1$ if and only if $y$ is actually the correct answer to $x$. But in practice the verifier can be imperfect.
Then $\Scal_x$, the set of answers the verifier accepts, isn’t the same as the set of correct answers: it can include wrong answers and leave out correct ones. This misspecification opens up regions of $\Scal_x$ that the model might learn to land in even though it’s not what we intended.

Thus reward-hacking comes from an imperfect verifier, which fails to capture what we truly want, as well as an imperfect sampling procedure which fails to stay away from these shortcut regions.

In the figure below, the dashed circle is the set of correct answers and the red ellipse is $\Scal_x$. The ellipse stretches back toward the prompt, so its wrong answers are the easiest to reach, and after training most paths land there.

This visualization also shows why scaling up RL (generating more samples and longer samples) makes reward hacking more likely. The more extensively we “fuzz” the verifier, the more likely we’ll find a path that lands in the misspecified region of $\Scal_x$. Once the model finds this shortcut, training pushes the model towards similar behavior.

## So what objective is reasoning solving?[#](https://alexwang.ai/posts/reasoning-as-pathfinding/#so-what-objective-is-reasoning-solving)

Reasoning isn’t actually solving any objective at all. A path is not guaranteed to converge to the correct answer. It’s only in aggregate, over the distribution of paths, do we get a high probability of success.

RL training directly raises the success probability $p_x$, by spending a lot of compute on searching for successful paths and then training the model to reproduce them. Thinking longer helps because training taught the model to use the extra tokens, not because generating more tokens is intrinsically better. The cost of sampling during RL is amortized into the weights. At inference time the model is likely to succeed with a single sample, but any individual sample is not guaranteed to succeed.
