It's just a cryptominer. On one hand that's not a big deal for victims on the other hand, I don't get interesting c o n t e n t to write about.

I wouldn't be surprised if threat actors deploy more sophisticated things. Plex may be hosted on residential IP and I think threat actors would love to have residential IP proxy to access corporate VPNs and emails. (edit: see update at the bottom. i do see proxy being deployed now)

Back on September 1st, 2026, Plex sent out emails and did a security announcement regarding important security updates. See the post here: [https://forums.plex.tv/t/important-security-update-for-plex-media-server-v1-43-2-and-earlier/942319](https://forums.plex.tv/t/important-security-update-for-plex-media-server-v1-43-2-and-earlier/942319)

As an infosec person and a Plex user, I was really curious about what this vuln was and if I could see in-the-wild exploitation. I set up a honeypot w/ a vulnerable Plex version running.

The details were limited and they said that they'd update the page with more details so I kept watching and didn't see anything.

Finally, on Sep 26th, I saw some CVE's get published here: [https://www.cvedetails.com/vulnerability-list/vendor_id-14994/year-2026/Plex.html](https://www.cvedetails.com/vulnerability-list/vendor_id-14994/year-2026/Plex.html)  but none of them had CVSS score of 9+. They did contain a link to a blog post which was not released at the time.

Link was to [https://zmain.info/blog/plex2shell](https://zmain.info/blog/plex2shell) and release was supposed to be mid Oct so I waited and finally saw an update on Oct 16th (yesterday). The author had discovered and chained several vulns together to get remote code exec which was pretty cool.
