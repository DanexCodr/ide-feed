A new open initiative under the Eclipse Foundation is aimed at bringing vendor neutral, standardized APIs to enterprise Java. The primary goal of the Jakarta Agentic AI project is to provide a standardized API that utilizes annotation driven agents, full Context and Dependency Injection (CDI) integration and a lightweight LLM facade to make it easy, consistent and reliable to build, deploy and run AI agents on Jakarta EE runtimes. Rather than requiring developers to hand roll agent orchestration or lock into proprietary frameworks, the initiative brings a consistent programming model to enterprise Java. Key aspects of the project's objectives include:

  * Standardized lifecycles and annotation model: Introducing common lifecycles and an annotation driven programming model (utilizing annotations like @Agent, @Trigger, @Decision, @Action and @Outcome) built on CDI.
  * Lightweight LLM Facade: Providing a minimal, pluggable abstraction (LargeLanguageModel) to interact with LLMs and integrate with existing frameworks (such as LangChain4j or Spring AI) without trying to standardize the fast changing LLMs themselves.
  * Enterprise platform alignment: Enabling AI agent workflows to integrate natively with core Jakarta EE specifications such as REST, Persistence, Validation, Security and Config.
  * Standalone portability and community innovation: Offering a standalone specification project under the Eclipse Foundation that promotes portability across Jakarta EE runtimes while allowing rapid iteration and experimentation.

As noted, Jakarta Agentic AI integrates with existing AI frameworks like LangChain4j and Spring AI through a pluggable, non invasive approach. Rather than attempting to standardize rapidly changing LLM provider APIs or replace existing frameworks, Jakarta Agentic AI acts as a vendor neutral orchestration and programming model layer on top of them. It leaves lower level model communication and prompt engineering to mature libraries like LangChain4j or Spring AI. For that reason, the specification introduces a minimal, pluggable LargeLanguageModel interface for sending prompts and retrieving typed or raw responses. Under the hood, an implementation of this interface can wrap a LangChain4j or Spring AI model instance. To avoid limiting developers to the lowest common denominator, the LargeLanguageModel facade provides an unwrap() escape hatch modeled after the unwrap() method in Jakarta Persistence (EntityManager). Finaly, because agents are CDI components, developers can use standard dependency injection (@Inject) to supply configured LargeLanguageModel instances or native framework components into their @Agent workflow steps. What got now released is 1.0.0-M1 milestone which delivers the foundational API surface and draft specification for public review:

  * Maven Central API artifact: The jakarta.agentic-ai:jakarta.agentic-ai-api:1.0.0-M1 library is live on Maven Central for early adopters and implementers.
  * Draft specification and javadoc: The draft specification document (published in PDF and HTML) and Javadocs are out for community feedback.
  * TCK milestone: An initial milestone artifact for the Technology Compatibility Kit (jakarta.agentic-ai-tck:1.0.0-M1).
  * Baseline requirement: Requires a minimum of Java SE 17 or higher.

On the roadmap beyond version 1.0, the Jakarta Agentic AI project aims to expand beyond basic static, annotation driven lifecycles toward dynamic, runtime flexible agent orchestration, including a fluent Java API to define, alter and manage agent workflows dynamically at runtime (rather than relying solely on static annotations at deployment time). It also looks to move beyond CDI events to support additional trigger types, such as Jakarta Messaging, REST POST endpoints, or direct programmatic invocations as well as support complex, multi branch decision logic and pre conditioned actions using Expression Language (EL) or programmatic workflow rules, moving past simple linear flows. Ultimately, the initiative seeks to ensure that Jakarta EE remains a modern, relevant ecosystem by enabling developers to build intelligent, agent driven applications securely and portably across various runtimes.
