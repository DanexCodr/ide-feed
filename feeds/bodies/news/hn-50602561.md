I love C, but often using it for parsing, tree walking or complex error handling leads to spaghetti code.<p>Of course there is Swift, Ocaml or Rust for situations like that, but then you are either forced to convert the entire codebase, or add a runtime library or go through the pain of bridging C to the new language.  Sometimes there are no compilers for the target architecture too when you are working on embedded stuff.<p>This is where Type-C comes in.  It works as a preprocessor like TypeScript and calls the original C driver behind the scenes.  Your code stays normal C for the most part, so you can predict how the code will be laid out. TypeC is a full superset of C11, so any C11 code compiles as is.<p>Want to use TypeC just for one file?  Rename to .tc and use the features you want, the rest of the codebase stays the same.  This works for kernel or baremetal code too as there is no runtime or extra libararies.<p>There are examples of TypeC code as well as real-world tests of converting existing code to TypeC on the GitHub page.<p>This is how the code looks like for an expression evaluator:
  type expr =
      | Num(int value)
      | Add(const expr <i>l, const expr </i>r)
      | Mul(const expr <i>l, const expr </i>r)
      | Div(const expr <i>l, const expr </i>r);<p><pre><code>  static result(int, eval_error)
  eval(const expr *e)
  {
      int d;

      match (*e) {
      case Num(value):
          return (Ok(value));
      case Add(l, r):
          return (fit((long long)try eval(l) + try eval(r)));
      case Mul(l, r):
          return (fit((long long)try eval(l) * try eval(r)));
      case Div(l, r):
          d = try eval(r);
          if (d == 0)
              return (Err(DivByZero));
          return (fit((long long)try eval(l) &#x2F; d));
      }
  }

  % typec -std=c11 -Wall -Wextra eval.tc
  $ .&#x2F;a.out
  14
  division by zero
</code></pre>
