A use-after-free in Ghostscript’s Type 1 font loader lets a crafted document cross Ghostscript’s `-dSAFER` sandbox, alter native path controls, and execute attacker-chosen commands as the rendering process.

Ghostscript sits beneath print, email, upload, and preview workflows. [Our ImageMagick research](https://pwn.ai/blog/imagemagick-from-arbitrary-file-read-to-rce-in-every-policy-zeroday) showed how files named `.png` or `.jpg` can still reach Ghostscript through image conversion. The index below records confirmed affected paths alongside additional applications whose renderer routes we traced.

Patch status

Ghostscript 10.08.0 fixes Upload2Shell. Debian backported the upstream change into its security package. [Ubuntu released fixed Ghostscript packages for seven supported releases on 21 October 2026](https://ubuntu.com/security/notices/USN-8949-1); its notice described our font-loader finding before the CVE number was assigned. Application teams also closed routes into the renderer: WordPress fixed the Author+ upload path under `CVE-2026-65640`, and Roundcube restricted unsafe attachment image types before ImageMagick conversion under `CVE-2026-114727`. [The technical writeup lists distribution package versions.](https://pwn.ai/upload2shell/research.html#distribution-packages)

We found several other Ghostscript issues with lower or comparable impact and reported them upstream. Ghostscript sits beneath more file-processing features than most applications expose directly. We expect the security community to find additional software that reaches this vulnerability through uploads, thumbnails, print jobs, and document imports.
