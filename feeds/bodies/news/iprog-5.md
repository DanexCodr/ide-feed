Google and Meta have released TorchTPU, an open source collaboration that introduces a native PyTorch backend for Google TPUs. TorchTPU can be used to execute models and migrate TPUs.  Tensor Processing Units (TPUs) are integrated circuits developed by Google for accelerating machine learning and artificial intelligence workloads. TPUs are better at handling tensors - multi-dimensional matrixes - that are used by neural networks such as TensorFlow, JAX, and PyTorch. TPUs were developed originally for TensorFlow, and have also been used with the JAX ecosystems. The new backend adds support for running PyTorch natively on TPUs. Programming Google's TPU from Python means using the XLA compiler stack. In 2020, Google introduced the first compiled version of PyTorch for TPU, PyTorch/XLA, based on Lazy Tensors. PyTorch outstripped the features of this, and developers found PyTorch/XLA was slow at compile-time and lacked support for PyTorch's native imperative ("eager") execution mode. Google says TorchTPU has been built as a principled TPU backend for PyTorch: eager execution is a top priority, and existing PyTorch workloads run out of the box with trivial code changes (e.g., .to("cuda") → .to("tpu")). The principles referred to start with the fact there are no JAX dependencies in the runtime, The Torch.compile() is based on Torch Dynamo rather than Lazy Tensor, and has a similar performance to JAX compile. By providing TPU collectives at the lowest level in the PyTorch stack, it has wide support for PyTorch distributed idioms such as DDP, FSDP, and DTensor.  Announcing the new collaboration, the TorchTPU team said that their focus was to make porting a workload to TPU as simple as changing model.to("cuda") to model.to("tpu"). They say obviously, you can't get peak TPU performance with that simple change, since a model's shapes, sharding and ops may be skewed toward a GPU architecture; however, the model should run out of the box. TorchPTU uses a JIT compilation approach for eager execution, with runtime optimizations that the team says can bridge the performance gap between op-by-op execution and compiled execution. The introduction of bounded dynamism, the avoidance of XLA recompilation due to shape changes, and the exploration of dynamic TPU kernels that can be precompiled ahead of time have all improved the TPU programming stack.  TorchTPU has built-in compatibility with Hugging Face's Transformers v5, Diffusers, and Kernels libraries, with out-of-box execution on the 5,000 most downloaded Hugging Face models.  TorchTPU is in active development, it is used in production for both inference and training workloads for some of the largest Google Cloud customers, and can be found as an Open Source project on GitHub.
