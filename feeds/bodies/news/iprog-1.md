While the current news is dominated by yet another round of patching driven by problems discovered by AI, Linus Torvalds says things might be getting better.  Software companies have certainly been scrambling to keep up with the seemingly never-ending run of vulnerabilities and problems discovered using AI, but writing in his weekly Linux kernel update post, Torvalds said that while the current set of updates were again driven by various AI fixes: _"this time around Alexei claims that on the bpf side at least the fixes are now coming in faster than the new reports, and that sounds lovely if true."_ Torvalds was referring to Alexei Starovoitov, co-creator and lead developer of the Extended Berkeley Packet Filter (eBPF), which is the technology behind running sandboxed programs within the Linux kernel. Torvalds continued: _"I think most other areas haven't reached that point yet, but it's at least a sign that we _may_ be starting to see the tide starting to turn. Don't hold your breath, but maybe cross your fingers we'll be getting there in the not entirely distant future."_ Torvalds was writing about the release of Linux 7.4 rc2, which he said is a big release.  The Linux developers have been experiencing similar situations to other software companies following the release of Anthropic Mythos bug-finding module. Mythos has been designed to be good at finding dormant, hard-to-spot, or decades-old software flaws (zero-day vulnerabilities) across major operating systems, browsers, and production codebases. As of November 2, 2026, Anthropic has disclosed 5,087 vulnerabilities across 680 open source projects. The company says _"To our knowledge, 629 of these have been patched. Across all findings in the ledger, 733 identifiers have been issued: 230 CVE records and 503 GitHub Security Advisories (a single finding may carry both). In other cases, maintainers have shipped a fix without publishing an advisory."_ High profile companies including Microsoft and Oracle have been busy this year issuing bug fixes, with Microsoft issuing updates to fix 974 problems in December, in addition to the 622 it issued fixes for in July. Meanwhile, Oracle issued a record 1,449 security patches in July, addressing 1,434 distinct Common Vulnerabilities and Exposures (CVEs) across 334 products and 32 product families.  Then there were the PHP memory-safety vulnerabilities that surfaced in October. These, collectively known as PHP2Shell under CVE-2026-109618 and CVE-2026-109619 affect core PHP interpreters and allow unauthenticated remote code execution (RCE). You know things are bad when mainstream media writes about it.  The problem is that AI can find security flaws, but it usually takes some human intervention to get to a solution, and many development teams, particularly in open-source software, don't have the resources to fix the problems faster than the attackers can make use of the vulnerabilities. So if Torvalds is right, and we're getting to the point where most of the obvious security vulnerabilities have been found, that has to be a good thing. In the words of the maestro _"that sounds lovely if true."_
