Can we build a family tree of ELIZA programs from the code itself? This page reports on the current state of the ELIZAGen code-phylogeny project, which treats ELIZA implementations like biological specimens and applies the tools of phylogenetics to them.

Over six decades ELIZA has been reimplemented hundreds of times: copied, ported across languages, rebuilt from published descriptions, simplified for teaching, and reimagined as art. Software has no material continuity of the kind that anchors biological or manuscript genealogies, so instead of comparing source text we compare *architecture*. Each program is described by a set of abstract features (does it rank keywords? does it have a backtracking matcher? does it keep a memory of earlier inputs?), and the resulting character matrix is analyzed with [PAUP*](https://paup.phylosolutions.com/), the standard parsimony software from evolutionary biology.

The current corpus contains **27 specimens** spanning 1965–2025 in eight languages, described by **13 binary features**. The work is in progress and is written up in a draft paper, [*Reconstructing Program Genealogies from Abstract Program Descriptions: The ELIZA Case Study (A Work in Progress)*](https://elizagen.org/genealogy/paper/ELIZAGen.pdf) (Jeff Shrager, December 2025).

## Reading the tree

**A basal polytomy of complete ELIZAs.** At the root sit programs that preserve the entire ELIZA architecture and are indistinguishable on these features: Weizenbaum's 1965 MAD-SLIP original, Bernie Cosell's 1966 BBN Lisp (written from the CACM paper without seeing Weizenbaum's code), several other Lisp versions, the 1970 SNOBOL and Burroughs B5500 Algol versions, a Java version, and Anthony Hay's 2021 C++ reconstruction. Six decades and very different languages, but the same design.

**A derived clade of simplifications.** Branching away from that core are mostly BASIC versions from the microcomputer era (descendants of Jeff Shrager's 1973 BASIC ELIZA, published in *Creative Computing* in 1977) together with Python, JavaScript and some simplified Lisp versions. These typically drop backtracking, memory and keyword priority, whether because of the limits of early microcomputers, for teaching purposes (e.g., Norvig's 1991 Lisp in *PAIP*), or simply because of a different programming culture.

**Validation specimens.** Three specimens test the method:

- A pair of byte-for-byte identical clones (E18, E20) land together with zero branch length, as they should.
- A control (E22, a pattern-matching file utility that has nothing to do with conversation) nests inside the ELIZA clade. The current features therefore capture general pattern-matching architecture rather than anything specifically conversational, and better conversational features are needed.
- LadyMouth (E21, Sarah Ciston's feminist critical-art chatbot) scores zero on every feature. It sits at maximal distance: it is an ELIZA-like program by role and critique, not by architecture, and serves as a confirmed outlier.

The paper argues that the result is best read not as a literal line of descent but as a map of a *textual tradition*, showing how implementations relate through preservation, adaptation, convergent reimplementation and critique.

## How it was made

1. Collect and normalize. Specimens were gathered from archives, publications and repositories, then lightly normalized (whitespace, comments, metadata).
2. Extract features with an LLM, then curate by hand. A language model proposed structural and behavioral features for a first program. The vocabulary was hand-edited, then expanded in a round-robin pass over all specimens until no new features appeared, with manual curation after each round.
3. Classify. Every specimen was scored on the frozen vocabulary, producing a program-by-feature matrix.
4. Infer trees. The matrix was converted to NEXUS and analyzed in PAUP* under parsimony (heuristic search, TBR branch swapping), and the resulting trees were drawn with Biopython.

## Data, code and paper

Everything is in the [genealogy folder](https://github.com/jeffshrager/elizagen.org/tree/master/genealogy) of the ELIZAGen GitHub repository:

- Draft paper: PDF · LaTeX source · bibliography
- Results: feature matrix (CSV) · feature vocabulary (YAML) · NEXUS file · trees · PAUP* log
- Pipeline: how-to and README · elizagen_library.py · cvs2nexus.py · draw_paup_trees.py
- Specimens: source code for all 27 programs
- Working notes: LLM conversations from the analysis

This project grew out of the 2022 blog post [A Code-Based ELIZA Phylogeny](https://elizagen.org/blog/a-code-based-eliza-phylogeny.html). If you know of an ELIZA implementation that should be in the corpus (especially pre-microcomputer, non-English, or artistic ones), please write to Jeff Shrager (jshrager@gmail.com).
