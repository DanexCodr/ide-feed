Amazon has released an AWS Emulator that can be used to build and test AWS applications locally on a developer's machine or in a continuous integration (CI) environment.  Amazon says that existing AWS SDK and CLI calls go to AWS Emulator and come back in milliseconds, meaning developers and coding agents can find and fix errors locally, with no deployments or AWS account required. It means a developer can test their software without calling AWS, on their own machine, or on a development server. Their requests go to the emulator, not to AWS. It's a local program that serves an AWS API endpoint. It has no graphical interface. To use it, once started, the developer sets environment variables to point the AWS CLI or an AWS SDK at its endpoint. They can then run their code as usual. In embedded mode, they pass the emulator’s HTTP client to their SDK instead. For the operations it supports, AWS Emulator returns the same result as AWS for valid calls and the same errors for invalid ones. The emulator keeps the state of the developer's resources in memory until it is stopped. Each copy started gets its own port, keys and in-memory state, so agents, test suites, and CI jobs never see each other's resources. For example, a coding agent can create an Amazon DynamoDB table, test against it offline, and fix its code before it deploys. Services in AWS Emulator are generated from the API models AWS publishes, the same models behind the AWS SDKs. When AWS adds a service or API, it shows up in AWS Emulator, and its behavior is filled in and verified release by release.  The emulator doesn't depend on an AWS region, and it has no additional service fee. You pay only for AWS resources when you deploy to AWS.  AWS Emulator is available now on GitHub or on AWS.
