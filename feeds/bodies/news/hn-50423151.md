### Microsoft Corporation UEFI CA 2011

Now some companies do allow employees to run linux right? Does that mean
          the CISO of those is just nuts and disables secure boot on his fleet?
          Turn's out that is a flat NO. There is this thing called Microsoft Corporation UEFI CA 2011
          and is used to sign 3rd party operating systems that can work with Microsoft keys
          that are installed on 99% of BIOSes out there. Okay so turns out secure boot
          can just work with ANY keys you can just make your own enroll them in your BIOS
          and sign your linux build with them and that's it it will just work.

Here is a screenshot of the bazzite OS tutorial on enrolling their keys inside of
          your BIOS. Okay so now we understand 2 things: 1. Microsoft has 3rd party keys for some linux distributions,
          2. If you can mess around in the BIOS you can just enroll your own keys.
          Now let's just sit with this and think what is secure about this? Like
          if I can just enroll my own keys how is this secure? Well turn's out
          secure boot was not to target consumers nor physical access to a machine,
          secure boot was only to stop one specific attack: EFI malware. Like if a malware
          is sitting on the EFI level and windows does not wipe EFI partitions on
          computer reset you have a "Immortal" malware excluding the fact that if you
          just wipe every partition this problem goes away but yeah that is besides
          the point.

Now so we know that Microsoft signs 3rd party OS for secure boot access
          but these OS are always changing and those keys don't change that often
          but the grub version the OS those things keep on moving so how come 1 key
          that never really changes unless expires changes but the software underneath
          changes all the time does that not break integrity of the boot chain?
          Well yes it does this is where something called a shim and MOK enrollement
          comes into play!

Okay here is a provided diagram of how MOK enrollment looks like. Do you

          Right so to get the SHIM installed you will need to take your EFI partition and
          mount it! From there you should see the following files:

Start with generating your keys with the following command:

```
openssl req -newkey rsa:4096 -nodes -keyout "./MOK.key" -new -x509 -sha256 -days 3650 -subj "/CN=some name/" -out "./MOK.crt"
```

Once you have your keys make sure you sign your kernel with the keys

```
sbsign --key "./MOK.key" --cert "./MOK.crt" --output /boot/vmlinuz-linux /boot/vmlinuz-linux
```

Side note to sign the kernel you cannot do that on a live USB unless you build it yourself.
          In the case of p3ng0s I specifically added a hook that does this during build time your can
          see it under the file `airootfs/etc/pacman.d/hooks/zzzz98-mok-signing.hook` of the V2 branch.
          But technically you can install for example kali linux directly to a USB drive: boot that drive and then sign that kernel
          then unboot the drive and do the EFI steps on that usb drive and you would have the same tech working on kali linux.
          Honestly to do this I recommend copy pasting this entire blog post into claude and asking him
          to generate you a tutorial and walk through that with him!

Okay next you need to rename the EFI file we found before to "grubx64.efi" and
          sign it:

```
mv ./BOOTx64.EFI ./grubx64.efi # rename
sbsign --key "/where_you_put_your_shim/MOK.key" --cert "/where_you_put_your_shim/MOK.crt" ./grubx64.efi --output ./grubx64.efi # sign grub
```

Okay after that you take your actual shim and name it "BOOTx64.EFI" and
          place the MOK software next to it:

```
cp -r "/path_to_your_shim/shimx64.efi" ./BOOTx64.EFI
cp -r "/path_to_your_shim/mmx64.efi" ./mmx64.efi
```

After that make sure you convert your certificates to a format secure boot
          will accept like so, and place the key inside of the EFI partition for quick
          access later:

```
openssl x509 -in "./MOK.crt" -outform DER -out ./borrowed-mok.der
```
