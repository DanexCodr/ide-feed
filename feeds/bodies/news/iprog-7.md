Apache Wicket 11 has been released. This is a major new version that lets an application drop jQuery entirely, uses less memory and time per component, moves to Java 21 and Jakarta EE 11, and rebuilds Wicket’s encryption on a single, authenticated API.  Wicket is a component-based web application framework for Java that is a rival to frameworks such as Tapestry. It has been in production for over 10 years, consists of Java code and HTML markup, and has Ajax functionality and a good selection of basic Ajax components. The first real change of note in the new version is support for Ajax without jQuery. Until now, Wicket’s client-side Ajax engine was built on jQuery, but Wicket 11 adds a second implementation in plain JavaScript with the same public API so you still get components such as Wicket.Ajax, Wicket.Event, Wicket.DOM and the rest. The other framework JavaScript (autocomplete, palette, upload progress, trap focus, the debug bar, native WebSockets) no longer uses jQuery at all, so one line removes jQuery from your application. jQuery does remain the default in Wicket 11, but the team says a future major release is likely to make the plain JavaScript engine the default, so this is a good moment to try it. This version is also described as faster and leaner, because Wicket 11 keeps a component’s model, behaviors and meta data in a single, simpler structure, and a link or Ajax component no longer carries extra bookkeeping for its behavior ids. Measured against Wicket 10 with the JMH benchmarks in the new wicket-benchmarks module, a page of components, serialized is about 40% smaller; reading a component's model takes half the time, and reading the behaviors of an Ajax component is 82% faster. Looking up a property, string resource or markup file happens up to 6.6 times faster, with 40–45% less allocation.  Wicket 11 has also been updated to use the current Java platform: Java 21 and Jakarta EE 11, with Jakarta Servlet 6.1.  This release adds support for Ajax veils. These are built-in UI behaviors that freeze or visually overlay web components while an background Ajax request is running. This is designed to prevent double-submits during slow asynchronous requests. When a user clicks a button or triggers an action that fires a slow Ajax request, a veil automatically drops over the UI. This stops the user from clicking the button a second time thinking they've not succeeded the first time, so preventing duplicate backend requests. It also stops them from clicking on other parts of the page that are about to be replaced or modified by the incoming Ajax response. Wicket 11 also replaces its two encryption APIs, one for URLs and one for the page store, with a single ICrypt that always uses authenticated encryption.  Wicket 11 is available now.
