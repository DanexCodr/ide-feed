GitLab 19.4 has been released with new options for cost efficiency when using agentic automatic. The update also includes GitLab's own MCP tools. GitLab is a web-based repository manager for Git that provides a centralized, integrated platform for web developers with features including source code management, CI/CD automation, and issue tracking in a single application.  The majority of the changes to the new version are in support for agentic automation. Developers can now delegate a whole objective from the terminal, run flows when a merge request opens, and reach GitLab from any Model Context Protocol (MCP) client through a governed set of tools. There are also new tool-level controls and per-person attribution to manage both access to the automation and the costs for how it is used. The GitLab team says these features come from the platform already running the work. The same permissions that cover the code govern the agents, and every credit traces to the user account that spent it, so there is no second permission model and no separate audit trail. A new command, /goal, has been added to provide developers with a way of telling GitLab what an overall task's objective is, and automates the management of the individual elements of the task. The /goal slash is part of GitLab Duo CLI. It automates a whole objective until it's done or reports what it could not resolve, with project guardrails and context. The agent implements the work, and a separate model verifies it against the stated goal at each step, deciding whether the goal is met or the iteration limit is hit. The developer can stop the run at any point, then revise the goal and restart, and the flow runs locally under the organization's existing rules. There are also new GitLab-Hosted open weight models as part of GitLab Duo Agent Platform. The three extra models are Kimi K3, MiniMax M3, and GLM 5.3. All three are Mixture-of-Experts (MoE) designs. Kimi 3 is a 2.8-trillion-parameter, open-weight multimodal model developed by Moonshot AI. MiniMax M3 is an open-weight, natively multimodal MoE model developed by MiniMax and designed for long-horizon agentic workflows. GLM-5.3 is an open-weight large language model (LLM) developed by Zhipu AI (operating internationally as Z.ai). GitLab says that by selecting models based on task requirements, teams can balance quality, latency, and cost. The new hosted open weight models in GitLab Duo Agent Platform get up to 4x more calls per GitLab Credit than many comparable frontier models, giving teams more model options to match cost to task complexity. There are also new MCP tools that mean an agent working in a client outside GitLab can now carry a piece of work through GitLab from end to end, without a person moving it between tools. New tools in the GitLab MCP server let it automate work across GitLab, triggering a pipeline and reading the trace of a failed job, running a merge request from opening through review to merge, searching and updating work items, and triaging vulnerabilities. Control over the tools is governed by administrator-set tools that use the rules defined for GitLab Duo Agent Platform, configured in the same group and project settings. Read-only tools default to Always Allow, while write and delete tools default to Always Ask.  This version also improves visibility of how agentic is being used, so a platform owner can show each department how it is using the organization's capacity for agentic automation, without waiting for an invoice. Per-user caps appear on a dedicated settings page, and usage exports go down to the billable event, arriving by email with a secure download link for both GitLab Flex and non-Flex subscriptions.  GitLab 19.4 is available now.
