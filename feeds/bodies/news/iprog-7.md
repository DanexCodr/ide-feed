The Firefox Devtools MCP for AI agent testing has been updated. The tool is a Model Context Protocol server that lets AI assistants inspect and control Firefox browser through the WebDriver BiDi.  The tool is intended for use by agents that want to use Firefox for regular browser tasks such as reading web pages or filling in forms. It can also be used in agent-assisted web development. In this case, the agent loads the page you are working on and inspects it with developer tools, such as the console, network requests, the debugger and the profiler. The tool works with a variety of MCP clients including Claude Code, Claude Desktop, Cursor and Cline. The tool controls Firefox through WebDriver BiDi (via Selenium WebDriver). WebDriver BiDi is a W3C standard protocol for browser automation. It expands the features of WebDriver (which provides one-way HTTP request and response) to instead use a WebSocket connection to offer real-time, two-way communication between an automation script and a web browser. The tool uses WebDriver Classic (Marionette) for features not yet ported to BiDi (notably Chrome context usage). It has local Firefox support, and can connect to custom Firefox builds such as local development builds, or typical release/beta/nightly/esr builds, that are present on your machine. It also offers real-time interaction, with live access to browser state and network activity. The tool also provides Firefox output capture with tdout/stderr capturing, including setting and reading MOZ_LOG. The main advantages of the tool are the support for agentic browsing, so AI assistants can navigate pages, fill out forms, handle multi-step flows, click elements, and take screenshots. The other support is for web development inspection, with tools to monitor console logs, network traffic, the debugger, and performance profiling. There are configurable profiles (slim, basic, developer, mozilla, all) to limit or expand what the AI agent can access. The description on GitHub points out that browser MCP servers carry inherent risks, and says you need to use a dedicated Firefox profile, and never run the server against your regular profile as the agent has access to whatever the browser can reach, including cookies and saved sessions. The updated version adds a new timeout setting that sets how many seconds a session waits without tool calls before it releases Firefox. The default stays 1800 seconds (30 minutes). Firefox accepts one client at a time, so a shorter delay lets other clients connect sooner. Other improvements are mainly to increase the use of BiDi, so the navigate history setting now uses WebDriver BiDi, and BiDi command errors now include the message sent by Firefox.
