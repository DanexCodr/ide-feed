Open the page and your phone is a node. The scheduler sends it a pod, and the pod's
            program runs on a Linux kernel booted in the tab. Close the tab and the node is gone,
            and Kubernetes starts the pod on someone else's.

## How it works

1. A tab joins. The join page holds a socket open to an agent beside the API server, and the agent registers a Node for the tab.
2. The scheduler sends a pod. The agent starts the pod's container with tabc, a container runtime whose containers run in browser tabs.
3. The tab boots Linux. A kernel compiled to WebAssembly runs the pod's program on the tab's CPU and memory. The pod's files and its address stay on the cluster's machine.

## A pod asks for a tab in one line

The control plane is an ordinary Kubernetes, and a pod is an ordinary pod. The marked line
          is the only one that is new: the scheduler puts a pod that has it on a tab, and every
          other pod on the cluster's own machine.
