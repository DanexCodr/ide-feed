Microsoft has announced the public preview of a HorizonDB PostgreSQL service for Fabric. The service is designed to make it easier to combine transactional and analytical workloads.  Microsoft Fabric is a data analytics product that combines elements of Microsoft Power BI, Azure Synapse, and Azure Data Factory into one unified software as a service (SaaS) platform, with data organized in a data repository called OneLake. Fabric HorizonDB is a new serverless PostgreSQL SaaS workload in the Fabric Databases portfolio. It lets users bring PostgreSQL application database into Microsoft Fabric, with service-managed infrastructure, usage-based consumption, automatic pause and resume, and an integrated extension ecosystem for AI and search. Applications connect using PostgreSQL protocol, and Fabric handles the compute, storage, and integration with analytical workloads. Fabric HorizonDB also connects the operational database to the rest of Fabric. This can happen in three ways; firstly, by mirroring operational data into OneLake. Secondly, by querying operational and analytical data through the same PostgreSQL endpoint; or thirdly, by loading curated analytical results back into PostgreSQL for application serving. Announcing the public preview at this year's Ignite conference, Microsoft's Silvano Coriani, Principal Program Manager on the Azure Data team, said that the result is an architecture in which transactions, analytical processing, and low-latency serving can use the appropriate execution path while applications retain a PostgreSQL interface. Fabric HorizonDB is a native SaaS database workload, not a PostgreSQL instance running in a virtual machine. However, users can connect through its PostgreSQL endpoint, and work with tables, relationships, transactions, indexes, and SQL using familiar PostgreSQL tools and drivers. Users don't need to configure a PostgreSQL host, or assemble a database image. HorizonDB handles that. The architecture also separates database compute from durable storage. Compute can stop when the database is idle without deleting the data.  Coriani said that this separation is important when considering OneLake. PostgreSQL's native tables and indexes live in the database's durable storage. Mirroring publishes an analytical representation into OneLake; OneLake is not the underlying storage engine for PostgreSQL transactions. The service manages infrastructure and server-level configuration. Developers still control the application data model: primary keys, constraints, indexes, SQL, and database-local permissions.  Developers can work on apps using Fabric's SQL editor, or can connect through Visual Studio Code and the PostgreSQL extension. The public preview of HorizonDB for Fabric is available now.
