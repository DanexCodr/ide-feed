It is coded completely in the C++20 STL, and it provides an interactive and beautiful TUI just through a user-input loop and ANSI codes.

If you are very confused as to what Corpustein is, it is a mini AI model that generates text token by token using a window of previous tokens (or words) and a container of all the possible n-grams (or groups of X tokens) based on the current window. This is what an N-gram Markov chain (plus a rolling window system) is. It also maintains a set of previously generated tokens to prevent repeating them, but allows common English words to be repeated. Corpustein is also the TUI that lets users interface with it. The thing that makes it different from what you probably think of when you hear "Artificial Intelligence" (most likely a Large Language Model) is that a Markov chain does not remember anything larger than its N-gram window, but an LLM has an attention model, which looks at a very long sequence of tokens to help generate responses. And, with LLMs, semantic similarity is automatically encoded as high-dimensional coordinates in a continuous vector space, while Markov Chains rely on matching exact word sequences. LLMs can also generate reasonable answers to questions they've never seen before because of how they learn more abstract rules, logic, and world knowledge. Whereas Markov Chains usually just repeat fragments of their training data. An LLM is also much slower than a Markov Chain and is way more resource-intensive. Think of Corpustein as a statistical or probabilistic model that generates mostly coherent English.

## Features

- **Fast and Lightweight:** Built only on the C++20 STL, Corpustein is fast and consumes virtually no resources.
- **Custom Corpus Loading:** Users can load custom corpus files to be used by Corpustein. Additionally, Corpustein comes with a vast array of default options already baked into the program for them to load.
- **Automatic Configuration:** Corpus files contain metadata that provides default settings for the model to use, determined by the content of the corpus by its creator. If the file appears to just be a normal text file without any sort of metadata, it will skip the default settings gracefully.
- **Compatibility:** With portable, native binaries automatically generated by the CI/CD for both Linux and Windows, Corpustein can be used on just about any system.
- **Commands and Settings:** Corpustein contains various commands users can run while in the interactive terminal environment to control many things about the model, like the order, maximum sentence count, and much more.
- **Alternate Terminal Buffer:** Corpustein uses an alternate terminal buffer to make a beautiful, stylized environment. Users are able to enable and disable this alternate terminal buffer right in the CLI.
- **Discrete Handling:** When the model runs out of token choices, instead of simply stopping the answer, it will choose a new, random token to continue generating text, with the user never knowing it ran out of tokens in the first place.
- **Context-Intelligent Repetition Avoidance:** Corpustein saves tokens to a history set to prevent repetition in its responses. It references tokens with a set of common English words to never force it into choosing a completely random token because of the avoidance of basic linguistic structural words
- **Configurable Typewriting Animation:** Instead of throwing the model's entire response to the terminal all at once because of how fast it is, it uses a configurable typewriting animation to make it more appealing.

## Devlogs

### 1: "Minimum Viable Product"

For the past 5.5 hours, I have been working on Corpustein. Corpustein is a Markov Chain built in C++20. I don't have a nice description or branding phrase yet, because I have been waiting for it actually to be slightly usable. Before I make my README, I will set up a GitHub Actions workflow to automatically compile Linux AppImage and Windows EXE files and attach them to Releases. How it works is that the user inputs a prompt, like "What is a transistor?" and the first step is finding a token for the program to start its response with. If you are wondering, a token is one unit of text. Usually, it is a word (that is, for Corpustein), but it could also be a character, punctuation mark, sentence, etc. It will compare the tokens in the user's prompt to the corpus to find a word the user said that is also in the corpus. And basic words like "in", "there", "a", "an", etc., can never be the seed. If it can't find a good seed based on the input text, it will just do a random one. It uses a rolling window where it stores three tokens at once, uses those tokens to find the best next token, and throws out the oldest token from the window so it's still only three tokens. Whenever it runs out of choices, it'll just go get a random window, continue, and everything will be okay. Currently, it has no way to know when to stop. That will be another thing I will do soon. It will just print text forever. The good thing is it doesn't repeat tokens, and it makes understandable sentences.

```text
====================
corpustein v0.1.0
====================

User: What is a transistor?
Corpustein: the transistor in 1947, which significantly compacted computers and led the digital transition. Information technology, particularly optical fiber and main electronic components (resistors, capacitors, etc.) can be created at a microscopic level. Nanoelectronics is Forest in 1914"
```

### 3: "Added some Settings"

I just added many settings to Corpustein, along with some features too! The first feature is that now, text is streamed to the terminal with a custom typewrite() function. It streams it character by character, waiting a specific amount of time between each one. A setting was added to control the delay between each character. This next setting is probably the most important one, though. I made it so the user can configure the order of the n-gram model. The order is how many tokens it references to figure out the next token. These two settings were originally their own, but I decided to instead make a /set command and put them in there, as /set delay and /set order. I also made a subcommand in /set called max_sentence_count that allows the user to configure how many sentences the model is allowed to output per response. It also automatically scales the maximum tokens per response to 40 times the new sentences. This setting can not be raised higher than 50. Another important thing isthat  I gave users the option to enable or disable the alternate buffer. That is pretty important, since if the alternate buffer is on, they can not do any scrolling, and everything is lost when the application is exited. Whereas, without the alternate terminal buffer, they can scroll and keep the responses after they exit the program. This can be accessed by the altbuffer subcommand in /set. Finally, I made it so anything starting with / but isn't a real command will just do the help command instead of outputting text.

### 4: "A lot of stuff"

Many changes have just been made. Most of these are really large architectural changes. So, here's an ORDERED BY SIGNIFICANCE numbered list.


![Corpustein showing many preloaded corpus options and stats](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/fgnmltotac94xnrcj8ri.png)

1. **User-Defined and Multiple Default Corpus Support:** Now, there are multiple default corpora, as opposed to just one. At the moment, there are 10, consisting of things such as the complete works of William Shakespeare, Mark Twain, and Charles Dickens, every single United States Presidential Inaugural Speech, the Linux Kernel Documentation, and more. Users can also load their own corpora by file path. This can be done with the command /load <type> <file>. Run /load help to view the types. The corpora start with a special format that starts off with a special file signature, then includes some default settings between the signature and the delimiter at the end (===). Here is how a heading looks:

```text
io.github.tyleruploads.corpustein:corpus-file
name: The name of the Corpus
default_order: An integer between 1 and 8 representing the order of the n-gram model
max_sentence_count: An integer representing the maximum sentences for each model's output, which also scales up the maximum tokens and the token history container.
===
```
2. **/stats command:** A brand new /stats command has been added! It outputs the name of the current corpus, along with many other things such as the tokens in said corpus, the unique N-gram contexts that occurred as a result of the corpus and the order, and some variables not inherently associated with the corpus, like the maximum sentence count and more.
3. **Static Assertion and Preprocessor Directive Right at the Top:** Right at the top of the code, a preprocessor directive and static assertion have been added (the static assertion is not in the preprocessor directive). The static assertion ensures it is being compiled with C++20 or higher. The preprocessor directive invokes an error when APP_VERSION is not defined, which prevents a big wall of fatal errors from being shown to the user with no context. APP_VERSION is automatically passed by CMake.

The model is programmed to never repeat tokens that are in its token history window, which is equal to four tenths of the maximum token count, which is 40 times greater than the maximum sentence count.
