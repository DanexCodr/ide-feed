Most of our time as software engineers isn't spent typing new code from scratch. We spend the majority of our day reading existing code: scanning pull request diffs, tracing stack traces in a split terminal, pairing with teammates, and reasoning through someone else's logic at the end of a long afternoon.

Yet many coding fonts still optimize for how code looks in a stylized marketing screenshot rather than how it feels after six hours of reviewing dense TypeScript generics, Rust lifetimes, or hexadecimal memory masks.

That observation led to **Sawala Mono**, an open-source, ergonomic monospace family built on top of the parametric [Iosevka](https://github.com/be5invis/Iosevka) engine. It is tuned specifically for code reading, pull request deliberation, and modern terminal workflows.

## Why the Name "Sawala"?

**Sawala** comes from the Sundanese word ***sawala***, which translates to *discussion*, *deliberation*, or *intellectual exchange*.

If you treat source code as a medium of communication between humans first and instructions for a compiler second, your typeface is the voice of that conversation. When a glyph is ambiguous, it introduces cognitive friction. When operators blur together or nesting levels are hard to tell apart, your eyes end up working harder than they need to.

On a practical level, **Sawala Mono** was also built with two everyday quality-of-life goals in mind:

1. **Zero Namespace Collisions:** If you have ever compiled custom Iosevka fonts, you know they can easily overwrite your existing system installation when they share the same family name. Sawala Mono registers under its own dedicated font family namespace (`Sawala Mono`, `Sawala Mono NL`, `Sawala Mono NF`, and `Sawala Mono NL NF`), so it installs cleanly alongside upstream Iosevka or any other monospace font.
2. **Pre-Compiled Opinionated Defaults:** Belleve Invis's upstream Iosevka is an extraordinary piece of typographic engineering. However, sifting through hundreds of character variants in `private-build-plans.toml` and waiting for local builds isn't something every developer wants to do before getting back to work. Sawala Mono ships a cohesive, tested configuration out of the box, complete with pre-built binaries and Nerd Font patches ready to download.

## Anatomical Choices That Actually Matter in Code Reviews

Every character variant in Sawala Mono's [`private-build-plans.toml`](https://github.com/Iosevka-Mayukai/sawala-mono-dev/blob/main/private-build-plans.toml) (`inherits = "ss03"`, `serifs = "sans"`) was chosen to solve specific legibility traps in daily programming.

![Card font comparison](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/sae0foxf4uwec00nmk11.png)
*Four core anatomical decisions in Sawala Mono: reverse-slashed zero, distinct `1`/`l`/`I` homoglyphs, high-contrast delimiters, and a 9.4° cursive italic.*

### 1. Reverse-Slashed Zero vs. Capital `O`

When inspecting hex literals (`0x0F_10 !== O0_FF`), UUIDs, or bitmasks at `12px` to `14px`, a dotted zero can sometimes fade out on lower-DPI monitors, while an unslashed zero is a bug waiting to happen. Sawala Mono uses a crisp reverse-slashed zero (`zero = "reverse-slashed"` in upright, `"tall-reverse-slashed"` in italic) that stays unmistakable at any font size.

### 2. Zero Confusion Between `1`, `l`, and `I`

Homoglyph collisions (`const Il1 = [1, l, I]`) are one of the oldest headaches in programming typography. Sawala Mono separates all three with distinct silhouettes:

- Digit **`1`** (`U+0031`) features a generous top serif and a wide flat base (`one = "base-long-top-serif"`).
- Lowercase **`l`** (`U+006C`) and **`i`** (`U+0069`) use asymmetric terminals (`ss03` upright and `serifed-semi-tailed` in italic).
- Uppercase **`I`** (`U+0049`) retains clear top and bottom crossbars.

### 3. High-Contrast Braces and Parentheses

In deeply nested callbacks, JSON payloads, or Lisp-style expressions, standard parentheses and curly braces often look too similar from a distance. Sawala Mono pairs flat-boundary curly braces (`brace = "curly-flat-boundary"`) with large-contour parentheses (`paren = "large-contour"`), creating clear visual anchors at block boundaries.

### 4. Dual-Persona Upright (`0°`) and Cursive Italic (`9.4°`)

Rather than mechanically slanting upright glyphs, Sawala Mono changes character construction when switching from Upright (`0°`) to Italic (`9.4°`):

- **Upright (`0°`):** Uses a grounded double-storey `a` (`double-storey-tailed`) and clean toothless corners (`b`, `d`, `p`, `q`) for a steady horizontal rhythm across dense code lines.
- **Italic (`9.4°`):** Transitions to a single-storey `a` (`single-storey-earless-corner-tailed`), single-storey `g` (`single-storey-earless-corner`), flat-hook `f` and `t`, and cursive `k` (`cursive-serifless`). The calibrated `9.4°` slope gives comments, keywords, and docstrings a distinct visual voice without feeling overly ornate or hard to read.

## Generous x-Height Without Losing Horizontal Density

One of Iosevka's greatest strengths is its horizontal efficiency. You can comfortably fit two or three vertical editor splits side by side on a laptop screen without horizontal scrolling.

Sawala Mono keeps that `500`-unit cell width (plus an optional `548`-unit **SemiExtended** width for high-DPI displays or presentations) and pairs it with an **x-height of `520`** against a **cap-height of `735`**.

![Sawala Mono with other font comparison](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/7xmmbcj2ue1itb2d0xtw.png)
*Comparing Sawala Mono's proportions (x-Height 520, Cap 735, Width 500) side-by-side against JetBrains Mono, Fira Mono, Inconsolata, and more.*

That **70.7% x-height-to-cap ratio** keeps the interior counters of lowercase letters (`a`, `e`, `g`, `s`, `m`, `n`) open and airy. Even if you drop your editor font size down to `12px` or `13px` to see more lines of context during a review, lowercase identifiers don't collapse into muddy blocks.

On the [live showcase](https://iosevka-mayukai.github.io/sawala-mono-dev/#comparison-slider-panel), you can drag a 50/50 split curtain to compare Sawala Mono directly against **JetBrains Mono**, **Inconsolata**, **Fira Mono**, **Reddit Mono**, **Victor Mono**, and **Ubuntu Mono** on the exact same JavaScript snippet.

## 55 Programming Ligatures or Pure Literal ASCII (Your Choice)

Developers tend to fall into two camps when it comes to programming ligatures: those who like how `=>`, `!==`, `->`, and `|>` reduce visual clutter, and those who want every single ASCII character rendered literally.

Sawala Mono treats both preferences as first-class citizens.

![Ligature grid](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/2wtllg2o99x0a0pj5hi6.png)
![Non Ligature Grid](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/zoxgb9uovxh3pay26d7f.png)
*Interactive ligature grid showing OpenType `calt` transformations alongside literal `Sawala Mono NL` rendering.*


In the standard **Sawala Mono** build (`ligations.inherits = "default-calt"`), **55 multi-character operators** fuse into crisp semantic symbols across five families:

- **Arrows (19):** `->`, `=>`, `<->`, `<=>`, `-->`, `==>`, `~>`, `<~~`, and more.
- **Equality & Logical (13):** `==`, `===`, `!=`, `!==`, `!===`, `<=`, `>=`, `||`, `??`, `///`.
- **Scopes & Pipelines (10):** `::`, `:::`, `:=`, `<:`, `|>`, `<|`, `<|>`, `<*>`, `..`, `...`.
- **Markup & Tags (7):** `<!--`, `/*`, `*/`, `</`, `/>`, `</>`, `<>`.
- **Arithmetic & Misc (6):** `---`, `+++`, `*=`, `*+`, `>>=`, `___`.

Most importantly, **ligatures never alter cell advance widths**. A three-character operator like `!==` or `===` still occupies exactly three `500`-unit monospace cells, so vertical column alignment in tables, comments, and `git diff` views stays pixel-accurate.

And if you prefer no ligatures at all? You don't even have to remember editor settings. Just install **Sawala Mono NL** (*No Ligatures*), which is compiled directly with `noLigation = true`.

Because all four packages are compiled from the exact same parametric metrics (9 weights from **Thin 100** to **Heavy 900**, 2 widths **Normal 500** and **SemiExtended 548**, and 2 slopes **0°** and **9.4°**), you can mix and match across your desktop without any visual mismatch between your IDE and your terminal:

## Getting Started in 60 Seconds

### 1. Download & Install

Grab the `.zip` archive for your preferred variant from the [GitHub Releases page](https://github.com/Iosevka-Mayukai/sawala-mono-dev/releases):

- **Windows 10/11:** Extract the ZIP, select all `.ttf` files, right-click, and choose **"Install for all users"** (this ensures Java-based IDEs like JetBrains pick up the font right away).
- **macOS:** Extract the ZIP and drag the `.ttf` files into **Font Book** (or copy them to `~/Library/Fonts/`).
- **Linux:** Copy the `.ttf` files into `~/.local/share/fonts/SawalaMono/` and refresh your font cache with `fc-cache -f -v`.

### 2. Configure Your Editor or Terminal

Here are quick copy-paste configs for popular setups (or use the interactive [IDE Config Generator](https://iosevka-mayukai.github.io/sawala-mono-dev/#setup) on the docs site):

![Sawala Mono IDE Configuration Generator](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/jrs9smy0q22xvatv2bsf.png)
*One-click configuration generator for VS Code, JetBrains, Neovim, Alacritty, Kitty, WezTerm, and Windows Terminal.*

**VS Code (`settings.json`):**

```json
{
  "editor.fontFamily": "'Sawala Mono', monospace",
  "editor.fontLigatures": true,
  "editor.fontSize": 14,
  "editor.lineHeight": 1.5
}
```

**Neovim / Neovide (`init.lua`):**

```lua
vim.o.guifont = "Sawala Mono NF:h14"
```

**WezTerm (`wezterm.lua`):**

```lua
local wezterm = require 'wezterm'
local config = wezterm.config_builder()

config.font = wezterm.font('Sawala Mono NF')
config.font_size = 14.0

return config
```

## Want to Tweak a Glyph? Fork and Build in the Cloud (Zero Local Setup)

One of the nicest parts of the repository setup is that **you don't need to install Node.js, `ttfautohint`, or Docker on your machine** if you want to customize a glyph or build your own spin of Sawala Mono.

The repository includes two automated GitHub Actions pipelines ([`build.yml`](https://github.com/Iosevka-Mayukai/sawala-mono-dev/blob/main/.github/workflows/build.yml) and [`patch-nerd-font.yml`](https://github.com/Iosevka-Mayukai/sawala-mono-dev/blob/main/.github/workflows/patch-nerd-font.yml)):

1. **Fork** the repository on GitHub and enable Actions on your fork.
2. Edit [`private-build-plans.toml`](https://github.com/Iosevka-Mayukai/sawala-mono-dev/blob/main/private-build-plans.toml) right in the browser if you want to swap a character variant.
3. Trigger the **Build Sawala Mono Font** workflow (and optionally the **Patch Nerd Font** workflow) via `workflow_dispatch`.
4. Within minutes, GitHub Actions compiles the TTF packages inside a containerized builder and attaches the ready-to-install `.zip` archives directly to your fork's Releases page.
